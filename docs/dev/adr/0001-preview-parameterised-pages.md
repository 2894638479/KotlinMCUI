# 预览拒绝参数不全有默认值的页面

预览会话按引用解析出页面，再用**反射零实参**调用它，所以它能接受的页面形状只有两种：只要 DSL 上下文，或者额外参数全部有默认值。判定过去是看编译器生成的 `name$default` 方法在不在——而它只要有一个参数带默认值就存在，于是"一部分必填、一部分有默认值"的页面会被接受并静默拿到 0/null：机器模式产出一张内容错误、却看起来合格的截图。现在判定改看 Kotlin 反射的 `KParameter.isOptional`，只要有一个额外参数没有默认值就拒绝并在日志里点名；**不提供任何强行放行的开关**，要预览这类页面就把它改写成全默认，或只取 DSL 上下文。

## 被否的备选

- **静默零值**（原行为）：实现最省，但它让"验收证据"这个概念失效——截图可能是任何东西，而错的那张不会自己报警。
- **加一个放行属性或注解**：保住能力，代价是接口里多一个只服务于诊断工具的开关；注解还更差一层，它会在后来有人新增必填参数时变成谎言。
- **打包 `kotlin-metadata-jvm`**（0.86 MB）读 `KmValueParameter.declaresDefaultValue`：判定同样精确，但要自己扛体积，而且它对覆写同样不等于 `isOptional`，换不到任何好处。

## 后果

- 运行期需要 `kotlin-reflect`。核心库只声明 `compileOnly`，由平台提供；Fabric 的语言加载器已经自带，其他环境缺失时带额外参数的页面一律被拒绝并说明。
- 想被预览的页面必须写成全默认参数，或只取 DSL 上下文。框架自己的页面都属于后者，不受影响。
- 判定只能看参数属性，所以"覆写继承默认值"这种形状要单独挡住——那种类没有 `name$default` 可调。

# 颜色控件
颜色控件属于高层包装（`widget` 包），但其中有两处设计值得记录：调色板是怎么画出来的，以及"画出来的颜色"与"点出来的颜色"如何保证一致。

## 方块调色板 = 一次四角渐变
固定色相下，HSV 的 `s` 与 `v` 都是线性的，于是饱和度/明度平面的四个角正好是：左上白、右上纯色相、左下黑、右下黑。这正是 `renderQuad(rect, lt, rt, lb, rb)` 的四角语义，所以整块调色板只用**一次** `renderQuad`：没有逐像素循环，也不需要纹理。

## 三角调色板必须走三角表
矩形的仿射变换永远是平行四边形，所以四角原语**无法**画三角形——把两个角重合成一条边需要奇异映射，那会把整个平面压扁。三角取色板因此依赖可选的 `DslBackendTriangles` 能力（`backend.triangles()`）；没有它时组合控件不提供该模式，而不是显示一块点不到的空白。

三角形三个角是纯色相、白、黑。逐顶点颜色由后端做线性（重心）插值，这也就是取色公式本身：`c = 色相权重 * 纯色相 + 白色权重`（黑的贡献是 0，所以三项只剩两项）。

## 看得见 = 点得到
取色把鼠标位置换算成重心坐标再算出颜色，与后端插值用的是同一套公式，因此不会出现"显示的渐变和点出来的颜色不一致"。方块同理，只是四角插值退化成两个独立的线性轴。

标记（当前颜色在调色板上的位置）需要**反解**。三角的反解利用了纯色相的通道构成——三个通道里必有一个是 1、一个是 0、一个在中间：

- 最小的通道就是白色权重（黑的贡献是 0）；
- 最大减最小就是色相权重（纯色相的那个 1）；
- 剩下的给黑。

## 两个实现细节
- **色相要记住**：灰阶（`s = 0`）的颜色反算出来的色相是 0，若直接读它，用户把饱和度拖到最左侧时调色板会突然跳回红色。因此每个调色板各自记住"最后一次有效色相"（`s > 0` 时的色相），方块与三角各记各的。
- **松开可能收不到**：在组件外松手时 `mouseUp` 不会送到这里，拖动会一直粘住。所以每帧渲染时用 `dslBackend.isMouseDown(MouseButton.LEFT)` 对账，发现按钮已经松开就结束拖动。拖动状态由事件增量维护、判定放在渲染期，也是为了这一点。
- **只认自己按下的事件**：拖动状态必须在**确认这次按下落在调色板内**之后才置位。按下事件会沿着树一路传到这里（在第一个返回 `true` 的组件处停止），按在别处时本组件虽然被访问过、却不应留下任何状态——否则随后的 `mouseUp` 会被它消费掉，传播在那个组件处停止，后面兄弟组件（比如滑条）永远收不到松开。这条规则对所有需要拖动的组件都成立。

## 已知取舍
- 拖动只能在**按下**时开始（`mouseMove` 不携带按键信息），并且依赖后端 `isMouseDown` 的准确性。
- 通过 `h`/`s`/`v` 改颜色会经 HSV 重新合成 RGB，字节量化会让其它通道有 ±1 的抖动；`s`、`v` 本身保持不变。
- 十六进制字段的 8 位形式是 `RRGGBBAA`，与框架内部的 `Color.ofARGB` 打包顺序不同；用户可见的格式以本控件为准。
